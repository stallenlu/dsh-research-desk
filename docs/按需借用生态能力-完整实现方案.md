## 1 目标与范围

### 1.1 目标（要达成的状态）

科灵台在既有科研流程状态机上，**按需、场景化地借用 dsh 生态的通用能力**，让用户在同一条科研工作流里无缝完成「找资料 → 精读 → 推选题 → 成稿配图 → 跑验证 → 导出排版」，而不感知能力来自哪个插件。判定标准只有一条：**用户仍能一眼看到研究走到哪、科灵在推进什么、哪里要自己拍板**（源自 1.2「过程可见」）。

### 1.2 七步工作流场景锚点

README.md:24 逐字：「把「记灵感 → 找资料 → 精读问答 → 推选题 → 写综述 → 跑验证 → 导出」这条科研工作流，做成侧栏里的一个面板，外加一个给 agent 用的工具入口。」七步按用户设计理念归为三类（详见第 2 节归属矩阵）：

| 七步（README.md:24） | 当前自建实现 | 是否借生态 |
| --- | --- | --- |
| 记灵感 | 灵感平铺时间流（README.md:70） | 否，核心自建 |
| 找资料 | 三源检索 `lib/search.mjs:6` SOURCES=['arxiv','europepmc','openalex']；全文抓取+分块+BM25（README.md:162） | **借**：浏览/抓 PDF/更多源 |
| 精读问答 | 有锚点问答+引文逐字核验（README.md:163） | 否，核心自建 |
| 推选题 | 假说表结构+可证伪选题（README.md:164-165） | 否，核心自建 |
| 写综述/成稿 | 多视角综述+研究缺口（README.md:166）、成稿三步（client.js:3330-3360） | **借**：配图生图（批次1） |
| 跑验证 | 外部 Python/Node（README.md:167「默认关闭，需先在设置里打开；受限目录运行」）+ 内置统计（README.md:168） | **借**：生态运行时 |
| 导出 | Markdown/BibTeX/JSON（README.md:169）；LaTeX/Typst 未做（README.md:176「宿主已有 dsh-cite 等可对接，尚未做」） | **借**：排版导出 |

### 1.3 关1调研硬结论（eco-scenario-probe，已逐字取证）

真正「不借外力干不完」的 4 处（其余节点是科灵台核心状态机自建）：
1. **找资料**：抓网/抓 PDF，自建仅三源（`lib/search.mjs:6`）。
2. **成稿/综述配图**：生图，科灵台无生图能力。
3. **跑验证**：外部 Python/Node 默认关闭（README.md:167）。
4. **导出排版**：LaTeX/Typst 未做（README.md:176）。

这 4 处即第 4 节四批次的切分依据。

### 1.4 定位硬约束（不可越界）

README.md:41 逐字：「它**不是**：通用文献管理器（Zotero 已做得很好）、同行评审裁判、选刊顾问，或替你做不可逆实验决策的自动机。它只做"研究流程的状态与证据链"，引文、PDF 与重计算交给更专业的工具。」
README.md:47 逐字：「把检索、核验、整理这些重复劳动交给科灵，把判断、审美与创造牢牢留给人自己。」
README.md:49 逐字：「能力边界要如实摆在你面前，而不是藏在文档里等你踩坑。」

## 3 接入架构：场景化借用的统一范式

### 3.1 复用现有底座，不造新管道

科灵台已有两条真实通路，本方案**复用而非新建**：
- **HTTP 桥**：client.js:206-211 `fetch(url, { method:'POST', headers:{'content-type':'application/json'}, body:JSON.stringify(payload||{}), signal:sig })`；client.js:201 180s 超时；client.js:215-217 首次 404 延迟 700ms 重试一次。ROUTE_PREFIX = '/api/research-desk/'（host.mjs:36），注册于 host.mjs:2401 `ctx.webServer.register({ kind:'prefix', path:ROUTE_PREFIX, handler:handle })`。
- **agent 工具入口**：host.mjs:2403-2424 `ctx.tools.register({ name:'research_desk', ... })`，execute 走 `run(args, signal)`（:2422）；状态里 `commands: ACTIONS.map(...)`（host.mjs:661）暴露真实 action 清单。

**明确不建**：通用工具面板、全局 tools 注册表膨胀、pre-execute 钩子。所有借用都挂在**已有科研节点**上，由状态机在场景触发点调用。

### 3.2 统一借用范式（六步）

以批次1（成稿配图）已落地的 media-desk 范式为模板，抽象出可复制到批次2-4 的统一范式：

1. **场景触发，而非面板罗列**：在某个科研节点（如成稿页）出现触发点，用户点「让科灵配一张图」这类**有底座的主行动**，不是摆出全部工具让用户填参数（依据 host.mjs:42 注释、1.2）。
2. **agent 侧公共接口发现**：`ctx.get('tools')`（image-tool.js:16），校验 `tools.executable / tools.execute / tools.selectExecutor` 均为 function（:17）；对候选名逐一 `tools.executable(name)`（:22），/// 校验参数与输出 schema（:23），再 `executor.describe([definition])?.schemas?.some(...)`（:25）确认可直接调用。**不发请求、不读凭证、不引用被借插件内部模块**（:1、:14）。
3. **副作用决策区拍板**：凡装包/改工作区/对外发包等高风险动作，走 `ensureRiskApproval`（host.mjs:596-617）：`gateCanProceed` 不放行则写一条 `pending:true` 的 waiting-human 决策（:611），前端决策区渲染「同意/否决」按钮（client.js:2446-2447），`answerDecision` 校验 `by==='human'`（host.mjs:1632）。**只读类借用（如查资料、生成预览）不触发拍板，但结果要走白名单回流**。
4. **execute 公共接口执行**：`tools.execute({ calls:[{ type:'tool-call', id, name, arguments:JSON.stringify(args) }], signal })`（image-tool.js:80），`id` 用 `media-desk:<uuid>` 类似前缀保证可追踪（:78）；带 300s AbortSignal.timeout 与组合 signal（:75-77）。
5. **结果白名单回流**：`batch.results?.find(e=>e.callId===id)?.result`（:82）；检查 `isError`（:83-85）、`value.paths?.[0]`（:87）；图片路径必须落在订阅插件生图目录白名单内、有界读取、有 MAX_BYTES 上限（:33-60，:12 `MAX_BYTES = 40_000_000`）。**只把白名单内的结果回流给科研节点，绝不把工具返回的任意路径变成文件读取接口**（:33）。
6. **工具不可用如实提示**：发现失败（`selected` 为空）返回明确中文提示「未找到订阅生图工具，或默认执行器不支持直接调用；请检查插件和执行器后刷新工作台」（:65）；`UNKNOWN_TOOL` 单独提示（:84）；不降级到伪造结果、不摆假按钮。

### 3.3 与既有研究_desk 工具注册的关系

- 借用能力**通过状态机 action 暴露**（如已入 ACTIONS 的 `draft_image`，host.mjs:40），仍经 `research_desk` 工具统一入口；不为每个生态工具新增全局注册。
- 副作用动作必须在状态机里登记 pending decision，才能进入决策区；这是「过程可见 + 人工拍板」的落点（1.2）。
- 借用结果写回科研状态（如把生成图挂到草稿节点），走既有 `store.mutate` 与证据链，不绕开 `applyOps`（host.mjs:611 同构）。

## 4 分批实施路线

> 每批给：最小切口 + 触发点 + 验收。批次之间**串行**：前一批五关确认通过才进下一批。

### 批次1：成稿配图借生图（当前实例，eco-illustrate-impl 正在做）

- **最小切口**：只借公共订阅生图接口（NAMES=dsh_subscriptions_image_generate / image_generate，image-tool.js:9），实现 `draft_image` action；白名单目录有界读取（image-tool.js:33-60）；不碰凭证、不建通用面板（host.mjs:42）。
- **触发点**：成稿页 hero 主行动区（client.js:3355-3361），复用 `.md-pill.is-primary`、不新增硬编码 hex、复用现存 class。
- **验收**：五关门禁；真机 GUI 截图（禁自建 headless 冒充）；配图结果挂到草稿节点且可追溯；工具不可用时如实提示。

### 批次2：找资料借浏览/抓 PDF

- **最小切口**：在「资料」页检索节点，除自建三源（lib/search.mjs:6）外，场景化调用生态浏览/抓 PDF 工具补更多源与全文；结果仍归一化进 `lib/desk.mjs` paper 形状（search.mjs:2-3）。
- **触发点**：资料页检索框 / 某条文献「抓全文」；只读借用，不触发拍板，但来源如实上屏（1.3）。
- **验收**：新增来源的文献可入库、去重（README.md:161 DOI→arXiv→PubMed→标题优先级）、引文仍能逐字核验；抓不到如实说「没找到」。

### 批次3：跑验证借运行时

- **最小切口**：保留 `runner.enabled` 闸门（host.mjs:1162-1164「没有开启外部工具调用…请打开 runner.enabled」）；在「虚空」实验节点场景化借生态运行时，装包/发包类副作用走 `ensureRiskApproval`（host.mjs:596）。
- **触发点**：靶心「交给科灵带队验证」；高风险动作前服务端写 pending、决策区「同意/否决」。
- **验收**：权限只降不升（host.mjs:619-636）；四条能力边界逐字上屏（client.js:2456 边界文案、charter.md:51-54）；不声称沙箱已隔离。

### 批次4：导出排版

- **最小切口**：在「导出」节点场景化对接宿主 dsh-cite 等，做 LaTeX/Typst/citekey（README.md:176「宿主已有 dsh-cite 等可对接，尚未做」）；保留现有 Markdown/BibTeX/JSON（README.md:169）。
- **触发点**：成稿页/复盘页的导出次要按钮（系统操作降次要，章程 2.5）。
- **验收**：导出内容可核验、密钥只导出「是否已配置」（README.md:169）；不把不可逆决策自动化。

## 5 安全闸门设计

1. **副作用人工拍板**：装包/发包/改工作区等高风险动作（approval.mjs:3 `HIGH_RISK_KINDS = ['install','workspace','outbound']`），必须先有同类人工 approve（host.mjs:584「装包与工作区改动前必须拿到人工 approve」），否则写 waiting-human pending（:611），停住流程（:607）。`collab_decision_answer` 只认 `by==='human'`（:1632）。
2. **权限只降不升**：`ensurePermissionDecision`（host.mjs:619-637）——请求档高于当前档时不升级，只留待决事项（:636「未升级；已在合作里留一条待决事项，等人工拍板」）；status 里 `current:'read-only'`、`upgradable:true`、note「选高档仅记偏好，高风险须人工拍板」（host.mjs:662-667）。
3. **不越 toolRegistry 边界**：toolRegistry.mjs:3-13 PERMISSION_BOUNDARY 逐字——三档权限「只约束 DSH agent 会话里的工具调用，完全不约束 runCode/installPackages 起的实验子进程」「实验代码当前只受 runner.enabled 与路径白名单约束」「沙箱 L1-L3 与本模块内的确认闸门能力均未在此实现，不得视为已约束」。借用一律走公共接口，不改这条边界、不自证安全。
4. **不造假按钮**：每个借用按钮必须有真实底座；无底座的第三方按钮明确不做（README.md:123）；工具不可用时如实提示（image-tool.js:65、:84）。
5. **结果白名单回流**：生图/抓取结果按白名单目录与 MAX_BYTES 有界读取（image-tool.js:33-60、:12）；任意工具返回路径不得变成文件读取接口（:33）。
6. **能力边界白话上屏**：四条边界逐字上屏（charter.md:51-54），client.js:2456 现有边界文案保持；不得写「扫描未命中不等于安全」制造虚假安全感（charter.md:53、:55）。

## 7 风险与不做清单

### 7.1 最大风险（三个）

1. **「场景化借用」退化为「通用工具面板」**：批次2-4 若图省事把浏览/PDF/运行时/导出做成罗列全部工具+手填参数的面板，直接违背 m20285 与用户否决口径，也违反 1.2（把配置负担丢回用户）。缓解：每个借用只挂具体科研节点的触发点，复用成稿页主行动范式（client.js:3360），五关关2 追溯表专门查此项。
2. **副作用绕过人工拍板 / 越 toolRegistry 边界**：借用生态工具时若在其内部触发装包、发包或外网动作，而状态机未写 pending、决策区未拍板，就破坏 1.2「决策点商量」与 1.3「边界如实」。缓解：所有副作用强制走 `ensureRiskApproval`（host.mjs:596-617）与 `by==='human'`（:1632），权限只降不升（:619-637），并逐字上屏 PERMISSION_BOUNDARY（toolRegistry.mjs:9-13）。
3. **工具不可用时的「假完成 / 假按钮」与结果污染**：生态工具缺失、执行器不支持或返回非法路径时，若伪造结果、摆无底座按钮、或把任意返回路径当文件读，就制造虚假安全感、违反 1.3。缓解：沿用 image-tool.js 的发现+schema 校验（:15-31）、isError/UNKNOWN_TOOL 如实提示（:83-85）、白名单目录+有界读取+MAX_BYTES（:33-60、:12），并禁自建 headless 自证（6.4）。

### 7.2 不做清单（硬边界）

- 不建通用工具面板、不注册全局 tools、不加 pre-execute 钩子。
- 不做通用文献管理器 / Zotero / 同行评审裁判 / 选刊顾问 / 不可逆决策自动机（README.md:41）。
- 不造假按钮、不罗列全场工具、不摆无底座第三方按钮（README.md:123）。
- 不自称已沙箱隔离 / 已静态扫描；不写「扫描未命中不等于安全」（charter.md:53、:55；toolRegistry.mjs:7、:13）。
- 不挂 1.4 / 1.7 作为方案依据；不用工作假设冒充定位（charter.md:15、:23-24）。
- 不碰 lib/client.js / lib/host.mjs / test 的越权改动（批次1 施工范围由专项代理负责，首席架构只写本文档）。
- 源码全绿不等于验收通过；不用写完文档或本地 headless 截图宣布「完成」。
