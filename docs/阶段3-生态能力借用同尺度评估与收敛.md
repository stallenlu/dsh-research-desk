## §2 共识与分歧的诚实切分

把 §1 的五维评级摊开后，**不能诚实地得出"某一条候选全维胜出"**。真实结构是：

- **无分歧的共识层**：D 的全部内容。四方（架构/后端/前端 + 阶段1测试侧）在"S3 不踩红线、S1 契合、S5 低风险、S2 真降本（虽有限）"上零分歧。**这是可以先做、不会错的部分**。
- **真实的分歧/待证层**：A 相对 D 的增量——把 4 项场景语义也声明化。降本潜力大（支持方），但强场景语义无损元数据化未验证 + 架构级引入风险（反对方）。**这不是价值取舍各执一词，核心是证据缺口**：`consumed` 一次性令牌、SSRF 防线、魔数校验能否进卡字段，本轮没有设计验证。
- **一致排除**：B（三方零分歧踩红线）。
- **一致挂起**：C（宿主 API 语义本环境不可得，非价值分歧而是证据不可得）。

**若硬把 A 或 D 单独封为"一致满意方案"，就是硬凑**：封 A 无视其架构级引入 + 强场景语义待证；封 D 则无视用户真实痛点"每加一类仍改 6-9 处"未根治。两者都必须如实呈现。

## §3 收敛结论：分两步走的满意方案

### 3.1 一句话结论
**收出口径 = "一致的底座 + 带前置验证的深度 + 一致排除 B + 一致挂起 C"**。这是能取得团队一致的最大公约数，且没有掩盖 A/D 之间的真实分歧。

### 3.2 第一步（无条件共识）：抽公共 helper —— 立即成立
把阶段1坐实"三处逐字同构"的六步管道（发现自检→selectExecutor→describe 验真→executable 查定义→execute→按 callId 取结果）抽成单一公共 helper；场景语义仍各能力自写。
- 证据：`host.mjs:51-64`/`:70-85`、`search.mjs:17-31`（阶段1:107 三处逐行同构）；`approval.mjs:1-57` 策略层不动。
- 收益：真降本 8-13 → 6-9 处（阶段1:132、后端 §5.4:138；**两来源均自带"静态估算/待量化"限定，6-9 处待测试侧量化**，与 §6 第二步"不填数字"口径一致），且 S1/S3/S4/S5 全绿、零产品方向风险。
- 这一步**不依赖 A 或 C 的任何待证项**，可独立推进。

### 3.3 第二步（带前置验证的深度）：场景语义声明化 —— 条件成立，前置未过不启动
在第一步底座之上，评估把 4 项场景语义（触发/取参/人话/闸门+注入）收进结构化声明。
- **启动前置（必须全过才动手，否则停在第一步）**：
  1. 强场景语义无损元数据化验证：生图 `consumed` 一次性令牌（host.mjs:1322）、SSRF 防线（:207）、魔数校验（:87-103）能否进卡字段且不退化第二套 DSL（后端 §7-2）；
  2. 安全字段不照抄被借工具注解——判定仍落 `approval.mjs` 层（MCP 规范两句、后端 §6:148）；
  3. 人话模板服务端算好成品白话、客户端零拼字段（前端 §7-3、R4）；
  4. 无"能力清单"UI 投影、五页签不动（前端 §7-1/§7-2）。
- 前置不过 = A 的增量不启动，**不因"声明式看起来更彻底"就强上**。

### 3.4 B 排除 / C 挂起重启条件
- **B：排除**。除非变成"带引擎强制网关的另类"（届时不叫纯 B，回到 A/C 讨论）。（后端 §6:149）
- **C：挂起**。重启条件=宿主 API 语义进入可证状态（app.asar 文档可读或宿主连接器 API 可查）；重启时必须守"科灵侧独立判定、绝不信注解"（后端 §6:150/:161）。若重启评估证实宿主桥接把注解当可信边界 → C 立即转红线排除（后端 §7-1）。
- 若最终选 C 落地，按用户口径在交付文档致谢 DSH 官方并加非官方/版权/免责声明（本文档为评估、不涉二次封装，故此处仅作落地提醒）。

### 3.5 分层结论的正确读法
本结论**不是"选 D 弃 A"**，而是"A 与 D 共享同一底座，先落底座、据 validated 证据决定是否再走声明化深度"。它同时满足"一致满意"（第一步全员同意）与"如实列分歧"（第二步的真实分歧与证据缺口白纸黑字保留），不硬凑。
