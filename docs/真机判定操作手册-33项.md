## 一、R1–R7 UI 第一眼 rubric（7 项）

> 判据：一般用户第一眼能不能看懂、知不知道自己该干什么。诚实 ≠ 把内部术语摊给用户。

**R1 四项主态可见**
- 步骤：进入科灵台首屏，看资料/选题/成稿/复盘四项主态。
- PASS：`md-i-line` + `md-metrics` 呈现四态，计数是 `state.json` 真实值（对照四项计数与 state 中实际条数一致）。
- FAIL 反证：计数为写死常量（改 state 后不变）、四项缺项。
- 证据：首屏截图 + 四项计数与 state 对应字段值。

**R2 五 Tab 页头结构**
- 步骤：看顶部导航。
- PASS：恰好五页签——灵感/资料/选题/虚空/复盘；无「文风」「排期」残留；结构清楚。
- FAIL 反证：页签数≠5、出现「文风/排期」、页头视觉混乱到分不清在哪。
- 证据：页头截图。

**R3 每页唯一主行动**
- 步骤：逐个进入灵感/资料/选题/虚空/复盘五页。
- PASS：每页恰有一个 `.is-primary` 动词按钮，一眼知道下一步点哪；无「高级/初级」类系统视角措辞。
- FAIL 反证：某页 0 个或多个主行动、主按钮是名词而非动词、出现「高级/初级」措辞。
- 证据：五页各一张截图。

**R4 无开发态/internal 词**
- 步骤：看完整个首屏与各页可见文案。
- PASS：首屏无 `DRAFT`/`PR-4`/`n_min`/`G6` 等内部合规术语；无「自检并就地重载/自检并重载」等开发态词；顶栏按钮为「刷新界面」。
- FAIL 反证：上述任一内部词/开发态词出现在正式界面。
- 证据：首屏截图 + 顶栏截图（此项直接复核 `98b2d2e` 提交）。

**R5 范式偏差**
- 步骤：看配色与排版，尤其宽屏下。
- PASS：无偏离宿主 token 的 `hex` 硬编码颜色（视觉与 DSH 原生一致）；无宽屏单列文字墙；示例数据与真实结论不混排。
- FAIL 反证：刺眼/突兀配色、宽屏下大段单列文字、示例和真结论混在一起分不清。
- 证据：宽屏截图（此项复核 `m12532/m12638` 类内嵌问题）。

**R6 能力边界四条**
- 步骤：找到能力边界/第一性原理文案区。
- PASS：四条逐字上屏（4/4），用户不会被误导为「已客观验证」。
- FAIL 反证：少于 4 条、措辞暗示已完成客观验证。
- 证据：文案区截图 + 逐条勾出的 4 条。

**R7 白话锚点 5 秒测试**（开始前先封存关键词）
- 步骤：验收人在看虚空页前，先独立封存一份「目标印象关键词」（参考方向：给科灵一个目标/带队验证/写下目标/白话提示，**不得提前透露给施工方**）。然后看虚空页主按钮 **5±0 秒**，立刻独立写下 10 个关键词。
- PASS：写下的 10 词命中封存关键词中的多数。
- FAIL 反证：几乎不命中，或需要施工方解释才知道按钮干嘛。
- 证据：封存表（含时间）+ 独立写下的 10 词纸面/截图。
