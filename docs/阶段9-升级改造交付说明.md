## 2. 缺口一 · 科灵主动提醒：改了什么

**借鉴对象**（阶段5 调研）：Readwise（恰当时机主动推回而非被动等查）、Anki-FSRS（从真实行为信号主动发起）、ResearchRabbit（偏好信号驱动）、LangGraph/Temporal（闸门密集下自动推进不绕闸门）。官方出处见 `docs/阶段5-同类产品成熟经验调研汇总.md`。

**落地**：四级流水线，全程只读分析 + 对话/界面人话提示。

1. **触发（真实事件驱动，不轮询）**：`scanOpportunities` `lib/host.mjs:669` 只在四类真实发生的变化上出候选——本周排期（`:681`，`noticeInThisWeek :649`）、搁置 14 天灵感（`:692`，`noticeStale :658`）、卡住 14 天假设（`:703`）、完成 7 天未复盘实验（`:715`）。无变化不空转；用户明确"少提醒这类"的类别直接不扫（`:674-678` muted）。
2. **有依据不臆断**：每条候选 `evidenceRefs` 必指真实行 id（`:688/:699/:711/:723`）；下发前 `toPublicNotices` `lib/host.mjs:730` 丢弃空证据/悬空引用（`:740-741`）、过滤未登记 kind（`:742`），最多 6 条（`:754`）。
3. **服务端算好人话**：`humanText` 是中文白话（如"本周有 N 条灵感排了期，要不要一起往下推？" `:685`），`detail` 给理由与例子（`:686/:663`）；下发对象只含 `text/detail/action`，**不暴露** `evidenceRefs` 裸 id、`verdict`、`suggestedAction`（`:743-752`）。
4. **有分寸不替人拍板**：提醒按钮只给反馈语义——`action: { id:'dismiss', label:'以后少提醒这类' }`（`:751`），**被提醒动作（suggestedAction）永不下发、永不自动执行**。点"少提醒"只记偏好，不执行被提醒的那件事。

**影响面**：`lib/host.mjs`（`NOTICE_KIND_LABELS :643`、`noticeInThisWeek :649`、`noticeStale :658`、`noticeExampleText :663`、`scanOpportunities :669`、`toPublicNotices :730`、`libraryView.notices :882-883`、`noticeAction :2249`、`syncSchedule :2276`、`ACTIONS :42` 加 `notice_action`/`sync_schedule`、`dispatch :2654-2655`）；`lib/desk.mjs`（`NOTICE_KINDS :91`、`scheduledAt :217`、`set_nudge_preference :926`、`update_inspiration` 白名单）；`lib/client.js`（`actNotice :937-940`、排期同步 `:1206-1208`、`renderNotices :3545-3555`）。

**风险与边界**：LLM 扫描成本/延迟本轮以"只在真实 state 变更后触发、失败静默跳过不阻断主流程"控制（方案§1.5:69）；提醒措辞用"要不要/比如"并附原文线索供人判断，不替人下冲突结论（方案§1.5:68）。**未新增持久化提醒实体、未加定时器改 state**（后端可行性判据：只读分析 + 对话输出放行，持久化/定时器改 state 必审闸门——本轮均未触发）。

## 4. 一般用户第一眼怎么用（守"服务端算好人话、客户端只渲染"）

> 遵循用户一贯口径，也守住前端"第一眼标准"：不摊内部术语、不造第二套界面、不做合规控制台。

1. **科灵提醒长啥样**：在原有"灵感建议"白话壳位置直接多出一条——`科灵提醒：本周有 3 条灵感排了期，要不要一起往下推？`（`lib/client.js:3551`，`text` 由服务端 `lib/host.mjs:685` 算好）。下面一行浅色小字给理由（`:3552`，如"它们都排在这周，放着不动容易过期。比如：……"）。空数组时整块自然不显示（`:3548`），**没有新提醒就不打扰**。
2. **怎么让它少提醒**：提醒下方一个白话按钮"以后少提醒这类"（`lib/client.js:3553`，文案来自 `lib/host.mjs:751`），点一下即记偏好（`:937-940` → `noticeAction :2249`），之后该类提醒不再主动提（`:674-678`）。全程不出现 kind 代码、evidenceRefs、accepted/dismissed 计数等内部字段。
3. **文风怎么生效**：用户在对话里透露稳定写作习惯、科灵记入画像后，之后写作自动套用该文风（`lib/client.js:911-912`），**不需要再手动选风格档位**——原"文风"功能以更好形态（画像自动化）合流，未恢复旧 Tab。
4. **排期从哪来**：原"排期"功能保留在灵感页（hero"N 条内容排在本周" `lib/client.js:3578/:3720`），本地排期全量同步进 state.json（`syncSchedule` `lib/host.mjs:2276`，真实 id 白名单 `:2280`、只写 `scheduledAt :2286`、失败静默降级），喂给主动提醒算人话——即决策卡§4"排期并入主动提醒"。
5. **不新增学习负担**：以上都长在已有界面与对话里，用户不需要理解"机会扫描/画像沉淀/配合偏好"这些词，看到的就是"科灵提醒 + 一个少提醒按钮 + 自动套用的文风"。
