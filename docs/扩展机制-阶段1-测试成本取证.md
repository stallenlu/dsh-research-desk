## 二、新增一类能力的补测成本量化

把一处借用的测试拆成 6 个成本层，逐层看三处各补了什么（这是**现状观察**，不是解法）：

| 成本层 | 抓全文 | 生图 | scihub |
|---|---|---|---|
| L1 发现/验真探针 | 2（host:1296/1309）+ search 内嵌 | 内嵌在 :1475/:1483 | 内嵌在 :2205 |
| L2 业务动作正向 | search:87 + host:511 | :1407/:1574 | :2167/:2182 |
| L3 副作用拍板闸门 | 无（只读） | **4**（:1379/1391/1430/1602） | 无（直接执行） |
| L4 注入防御/注入边界 | search:134 + host:511 不可信标记 | 无外部文本注入 | 无外部文本注入 |
| L5 失败降级/不可用诚实 | search:100/114/125 + host:533 | :1445/1457/1475/1483 + HTTP 失败簇 | :2195/2205/2216 |
| L6 UI/设置静态护栏 | 无 | settings:117/126/136 + client-ui ~10 断言 | 无 |
| **合计（独立 test）** | **14** | **29 + 3 + UI断言** | **6** |

**核心事实（不夸大不缩小）**：
1. 新增一类能力的补测量不是固定值，取决于它落在哪几层。三处从 6 条（scihub，无拍板无注入无回退）到 29+ 条（生图，全层）不等，跨度近 5 倍。
2. 成本不为零的共性部分（L1 发现验真探针 + L2 业务正向 + L5 失败降级）三处都要补——这部分与能力种类无关，是每次复用的固定开销。
3. 成本差异大的部分是 L3 副作用拍板闸门、L4 注入防御、L6 UI 护栏、以及生图独有的 HTTP 直连回退与安全簇（魔数/SSRF/协议状态机）。这些是**场景语义**，随能力性质增减。
4. 每处借用各有一套独立的 mock 辅助（抓全文 WEB_FETCH_DEF、生图 DRAFT_DEF、scihub scihubTools），互不复用——新增能力需再写一套自己的 ctx/tools 验真 mock。
